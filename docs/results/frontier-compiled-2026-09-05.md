# フロンティア DP の遷移コンパイル（2026-09-05）

## 対象と結論の範囲

対象は `src/cuda/b300/oneesan_cuda_gridfp_b300_hbm32_factorized_reverse2_row6crt20_batch.cu`。
このソルバーは格子の対角の頂点を結ぶ単純路を厳密に数える。フロンティアの接続状態を
N/R/L の列で表現し、通常状態と blocked 状態を別々に保持する。左右の部分列を分解して
状態番号を計算し、先頭部分には n=27 では row6、小さい設定では row5 などのオートマトンを使う。その後は占有マスクで分割した
グループを更新し、複数の素数による剰余から CRT で整数を復元する。

今回の中心は、同じ局所遷移を何度も rank/unrank で構築する代わりに、同型のグループで
共有する疎な遷移表にコンパイルする変更である。**DP の状態数そのものは減らしていない。**
実測機は RTX 3070 8 GiB、CUDA 13.3、sm_86。n=27/B300 の速度は実測していない。
表に入らない大きなグループは従来の逆遷移カーネルに戻るため、小規模での倍率をそのまま
n=27 に適用できない。

測定結果は末尾に記録する。数倍の高速化を達成したという主張ではない。

## 実装

- `factor_transfer_map.cuh`: 一段・二段の遷移を入力状態番号の列にコンパイルする。
  32-bit CSR の列番号・オフセットを使い、通常状態の恒等遷移を暗黙に保持する。
  GPU で整数として加算し、各出力について最後に一度だけ正確な剰余を取る。
- 固定側、占有数、ウィンドウ両端、通常/blocked 状態数をキーに、直前の形状の表を共有する。
  占有位置ごと、行ごとの DP 値を共有・同一視することはしない。
- 左端 p=1 の逆遷移も導出した。表を使うグループでは、この境界での atomic 加算も不要になる。
  p=2 と p=1 を一つの表に合成できる。
- 表を使う場合、従来の MateID キャッシュ領域にグローバル状態番号を保存し、scatter の
  rank/unrank を省く。領域が確保できない場合はその場で計算する。
- `factor_global_index` は factor-unrank と global-rank の合成を直接計算する。
  自由側の rank は入力の商・余りに既に含まれているため、再度表から求めない。
  この変更は遷移表を使用しない経路にも適用される。
- 低い側だけが変わる合法な局所遷移では `rank' = rank - low_rank + low_rank'` を使う。
- グループ全体の CUDA graph を同じストリームに順に投入し、ウィンドウ境界で各 GPU を同期する。
  cfg 転送、graph、次の cfg 転送の順序を維持する。全 worker の同期後に次のウィンドウへ進む。
  待ち時間は `active_sum_s` と `group_graph_sum_s` に含める。

## 正確性の説明

### 固定領域の空き位置の移動に対する不変性

同じ固定側に、占有数の等しい二つのマスク a, b を置く。a の k 番目の占有位置の R/L を
b の k 番目へ移し、残りを N とする写像を φ とする。活動領域と中央の記号は変更しない。

1. N は高さを変えない。したがって占有記号の列を保つ φ は高さの非負性、端点の対応、
   最終高さを保ち、合法な状態の間の全単射になる。
2. 固定側で比較されるのは同じ位置集合上の R/L の向きである。最初に異なる占有記号の
   順序は φ で保たれるため、その部分列の辞書式 rank は不変である。
3. factor block のサイズ・stride は固定側の占有数と接続高さで定まり、空き位置そのものに
   依存しない。自由側と中央記号は不変なので、グループ内の通常/blocked rank も不変になる。
4. 活動領域内の局所書き換えは φ と可換である。遠い接続先を探す走査も、N を通過して
   同じ順序の R/L を調べるため、同じ候補を同じ多重度で列挙する。

従って、φ によって同じ rank に対応する出力は、同じ入力 rank の列を持つ。
これは単に幅を縮めて境界の位置を変える操作ではない。元の幅と p を固定したまま、
**非活動領域だけ**の空き位置を移動する証明である。p=1 の規則もそのまま保つ。
実装は両側、窓の両端、両セクターのサイズをキャッシュキーに含める。

### 左端 p=1 の逆遷移

通常状態の除外枝は恒等写像で、blocked の除外枝は位置 1 に N を挿入する。
含む枝の逆像は、出力の下位二記号に応じて次になる。

| 出力 | 含む枝の入力 |
|---|---|
| LR | NN |
| NR / NL | RN / LN |
| RN / LN | NR / NL |
| NN | 合法な RL、および上側の接続先を戻す RR の候補 |
| その他 | なし |

LL の下側の接続先は p=1 には存在しない。NN の逆像は、下位の N を一つ取り除いて
内部の閉路接続の逆列挙式を p=1 で適用すると得られる。RL の高さ条件と RR の走査条件は
変わらない。これは `reverse_boundary_main_predecessors` に実装し、別の順方向列挙を
反転した関係と、幅 3〜12 の全合法状態について照合している。

### 合成、多重度、恒等枝の省略

一段の整数転送行列を T_p とすると、二段は T_(p-1) T_p である。
各中間状態の逆像をさらに逆列挙することで、積の項をすべて列挙する。同じ入力に到達する
複数の枝は別々に保存する。重複を取り除くと経路数が変わるため、重複は保持する。

通常出力の最初の枝は、一段なら恒等枝、二段なら二つの恒等枝の合成であり、必ず入力 i
を一度含む。その一項だけを表から除き、加算の初期値を `in[i]` にする。
他の同じ入力 i があっても除去しない。検証カーネルは先頭項が本当に i であることも確認する。

内部の通常出力の一段の入力数は高々 3、blocked 出力は高々 W。
境界の通常出力は高々 W+2 個の通常入力と一つの blocked 入力を持つ。
二段の入力数には W>=3 で 6W という上界を使える。
W<=28、32-bit 剰余なので、未還元の整数和は `168*(2^32-1) < 2^40` であり、
64-bit 加算はオーバーフローしない。正確な逆数除算で最後に還元することは、各項で
剰余を取ることと同値である。

32-bit prefix-scan は `total <= floor(UINT32_MAX/(6W))` の場合だけ実行する。
列番号も通常と blocked を合わせたローカル番号であり、INT_MAX 未満のグループに限定する。
この制限を超えるグループは従来経路で処理する。

### グローバル番号の直接計算

factor block 内で `i-off = hr*stride + lr` と分解する。自由側なら hr または lr は
そのまま全状態における部分列 rank であり、固定側だけをマスク付き rank から変換すればよい。
高い側のグローバル基底、中央記号までの既知の DP 項、低い側の rank を加える式は、
元の `global_rank(unrank(i))` と同じである。MateID が必要な場合だけ自由側の記号列も読む。

低い側の局所 rank 差分は、固定側が高い側で、変更位置 p が LOW_LUT_K より小さいときだけ
使う。対象の LR→NN / NR→RN / NL→LN は高さの差を変えないため、factor block と高い側の
項は不変である。元の rank は `base + low_rank` なので引き算のアンダーフローもない。

## メモリ、graph、設定

`GRIDFP_TRANSFER_MAP_MIB=512` が既定の表の上限。`0` なら無効。
既存の DP 配列と scratch を確保した後の空き容量から、将来の scratch 増加と 256 MiB を
残して表を作る。全ステップが入らなければ途中の表を破棄し、従来経路に戻る。
占有数 0 または固定幅のグループは同型マスクが一つなので、表を作らない。
表は scratch の予算とは別枠で、実際の最大容量を `transfer_peak_mib` に出力する。
planner は必須 DP メモリとは別に `optional_transfer_cap_mib` と
`dp_peak_with_transfer_cap_gib` を出力する。表の構築用一時領域は永続表のピークには含まれない。

表を解放する前にそのポインタを参照する graph を破棄する。scratch の再確保時にも graph
を無効化する。表を使う経路かどうかを graph のキーに含める。キューに投入済みの処理は
CUDA のストリーム順序と解放時の同期に従う。cfg のホスト領域は schedule 全体の寿命を持つ。

- `GRIDFP_VERIFY_TRANSFER_MAPS=1`: 各グループの全出力の逆像を再列挙し、表と順序・多重度まで照合する。
- `GRIDFP_CACHE_GLOBAL_RANK=0`: 表を使う経路のグローバル番号キャッシュを無効にする。
- `GRIDFP_PIPELINE_GROUPS=0`: グループごとの同期に戻す。
- `GRIDFP_DIRECT_GLOBAL_INDEX=0` / `GRIDFP_LOW_RANK_DELTA=0`: コンパイル時の比較用。
- `GRIDFP_FRONTIER_THREADS`: 32〜1024 の 2 の冪。既定 256。
- `GRIDFP_FRONTIER_BLOCKS`: grid-stride kernel のブロック数上限。既定 0 は上限追加なし。

追加の任意機能 `GRIDFP_TERNARY_RANK_LAYOUT=1` は N/R/L の rank 表を 4^L から 3^L に詰める。
W=28 の二つの dense rank 表は合計 1280 MiB から約 24.4 MiB になるが、変換処理によって
n=20 は遅くなったため **既定は無効**。これは転送表とは独立したメモリ節約機能である。
`GRIDFP_TRIT_CHUNK` は 4 または 7（既定 7）。定数メモリに置く任意の
`GRIDFP_TRIT_CONSTANT=1` は chunk=4 だけに限定する。

## 採用しなかった実験

これらは探索時の単発測定・小規模スクリーニングであり、最終の反復比較とは区別する。

| 実験 | n=20 の観測 | 判断 |
|---|---|---|
| 固定マスク向けの追加 rank 表 | 約 7.91→8.35 秒 | 実装を撤去 |
| 3 進 rank 表、chunk=7 | 約 8.57 秒 | 任意機能、既定無効 |
| 32-bit CSR、境界対応前 | 約 7.72 秒（global rank cache 込み） | 後続改善の基点 |
| warp 単位 ELLPACK | 約 7.99 秒 | 実装を撤去 |
| 3 / 4 セルの表合成 | 約 8.60 / 9.89 秒 | 構築と読出しが増え、撤去 |
| 2 / 4 スレッドで一出力を計算 | 約 7.34 / 8.74 秒 | 1 スレッド版の約 7.04 秒に劣り、撤去 |

## 再実行

同じソースから、今回の変更群を無効/有効にして交互に測定する:

```sh
python scripts/bench/bench_factor_division.py --optimization frontier-compiled --n 20 --arch sm_86 --repeats 6
```

個別の比較には `--optimization transfer` または `direct-index` を使う。
ビルドは GPU 測定前に終え、初回のウォームアップを集計から除く。
測定対象は各剰余の `wall_s` で、prefix 計算、遷移表の作成、graph 再構築、最終和を含む。
共通の factor 表作成・確保・schedule 準備と、剰余切替時の配列ゼロ化はこのタイマーの外側である。

## 最終の反復測定

比較対象は直前の全グループ graph 版（このセッションで凍結したバイナリ）。
ウォームアップを除いて n=20 は各 6 回、n=21 は各 4 回。AB/BA の順序を交互に変えた。
全実行の剰余が既知値に一致した。

| n | 直前版の中央値 | 今回の中央値 | 時間短縮 | 速度比 | 遷移表ピーク/GPU |
|---|---:|---:|---:|---:|---:|

| 21 | 23.08360 s | 20.41490 s | 11.56% | 1.131x | 447.556 MiB |

表の構築時間の中央値は n=20: 0.427 秒, n=21: 0.927 秒。これも上の計算時間に含まれる。

生データ、コンパイル条件、ソースの SHA-256 は [JSON](frontier-compiled-2026-09-05.json) に保存。
GPU メモリ帯域のハードウェアカウンターは採っておらず、「メモリ律速になった」とは断定しない。
状態数を指数的に削減する数学的ブレークスルーには到達していない。

## 検証結果

- CPU/UBSan: 境界も含む幅 3〜12 の全列挙で 187,583 出力・229,346 入力枝を
  独立した順方向の関係と照合。既存の幅 28 の境界・260,000 標本テストも成功。
- GPU: 擬似乱数の入力に対し、従来の atomic を使う順方向の処理と一段/二段の表を比較。
  両窓、全ての非自明なマスク、3 法で 264 ケース・51,138 状態が一致。
- GPU の rank/unrank および直接 global index: W=19 の両側・6 グループ、
  1,807,570 状態で元の計算と一致。通常表と任意の 3 進表の両方で成功。
  低い側の rank 差分も 1,886,184 個の合法な前状態で一致。
- n=9: graph の 3 設定、blocked cache の有無、単一/二重ストリーム、表の有無、
  グループ同期の有無の **48 条件 × 2 法 = 96 結果**で既知の剰余が全て一致。
  表を使う条件では全マスクについて逆像の順序・多重度も照合。
- Compute Sanitizer memcheck: 順方向オラクル、実行中 graph を残したままの arena 拡張、
  n=9 の 2 法・構造検証で **0 errors**。
- n=20、scratch 40 MiB、全マスクの構造検証を有効にして 2 法の既知値に一致。
  表の上限を 1 MiB にした試験では全 330 形状が fallback し、既知値に一致。
  n=9 で global rank cache を無効にした経路も 2 法で一致。
- n=20/n=21 の反復測定の全剰余が既知値に一致。
- n=27 / LOW=14 / HIGH=13 の sm_103 cubin コンパイル成功。
  B300、複数 GPU の実行検証はこのマシンでは行っていない。
- 3 進変換の CPU 全列挙: 長さ 0〜14 の 7,174,453 語で scalar/chunk4/chunk7 が一致。

GPU の主要検証は `scripts/test/gridfp-reverse.sh --gpu`、設定の組合せは
`scripts/test/frontier-runtime.py <n9 のバイナリ>` で再実行できる。
今回実施したのは変更箇所に対応する検証であり、リポジトリ全体の全テストの成功を主張するものではない。
