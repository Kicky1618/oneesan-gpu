# Oneesan GPU solver — H100 build

Primary source: `src/cuda/hopper/oneesan_cuda_h100.cu`

Design:
- Frontier DP over grid edges.
- 192-bit canonical state key.
- 5-bit component labels.
- Start/target component IDs stored directly instead of 2-bit flags per component.
- GPU open-addressing hash table with generation tags.
- Dense state/value arrays; hash table stores only key + dense index.
- 8 residues are propagated in one traversal.
- Raw CUDA buffers are reused between layers.

Supported width:
- `MAXW=24`, so n <= 23 with current 192-bit encoding.

Build for H100 (Hopper, sm_90):
```bash
./scripts/build/h100.sh
```

Run:
```bash
./build/oneesan_cuda_h100 16
```

Output contains 8 residues. For n > 15, 8 x ~61-bit CRT may not cover the trivial edge-subset bound. Add more primes / residues before claiming an exact integer.
